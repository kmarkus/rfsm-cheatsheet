\section{Specifying rFSM Models}

\begin{verbatim}
    local rfsm = require("rfsm")
    return rfsm.state {
       ...
    }
\end{verbatim}

\subsubsection{Description}

A rFSM model is contained in a file that returns the toplevel state.
\texttt{LUA\_PATH} must contain \texttt{rFSM/src/?.lua} and
\texttt{rFSM/src/?/init.lua}.

\subsection{Toplevel rFSM Configuration}

The following fields may be defined in the toplevel state:

\begin{itemize}
\item \texttt{getevents()}: function that will be executed
  during step/run and must return a table of new events (index part
  only).
\item \texttt{dbg}, \texttt{info}, \texttt{warn}, \texttt{err}: log
  functions. Must accept multiple parameters to log. \texttt{false}
  disables. Defaults: \texttt{dbg} off, \texttt{info} stdout,
  \texttt{warn} and \texttt{err} stderr.
\end{itemize}


%%% States
\subsection{States}

States are the principal building block of rFSM Statecharts.

\begin{verbatim}
    rfsm.state {
       entry=function() do_this() end,
       exit=function() do_that() end,

       substate1=rfsm.state{...}, ...
       rfsm.trans{...}, ...
    }
\end{verbatim}

\subsubsection{Fields}

\begin{itemize}
\item \texttt{entry(fsm, state, 'entry')}: entry function
\item \texttt{exit(fsm, state, 'exit')}: exit function
\item \texttt{doo(fsm, state, 'doo')}: doo function/coroutine (only
  permitted for leaf states)
\end{itemize}

\subsubsection{Description}

States model distinguishable conditions and encapsulate behavior. If a
state has substates it is called a \textbf{composite state}. Otherwise
it is called a \textbf{leaf state}. If a transition ends on a
composite state, this state must define an initial
transition. \texttt{sista\{\}} and \texttt{csta\{\}} are aliases of
\texttt{state\{\}}. \textbf{Common error:} forgetting the commas.

\subsubsection{The doo function}

A plain \texttt{doo} runs once, then the completion event
\texttt{e\_done} is raised. A long running \texttt{doo} must call
\texttt{rfsm.yield(idle)} regularly to let transitions fire:
\texttt{true} lets the fsm go idle, \texttt{false} (default) calls
\texttt{doo} again in a tight loop.

\subsection{Transitions}

Transitions connect states.

\begin{verbatim}
    rfsm.transition{ src="stateX", tgt="stateY",
                     events={"e_1", "e_2"} }
    rfsm.trans{ ... } -- short form
\end{verbatim}

\subsubsection{Fields}

\begin{itemize}
\item \texttt{src=<state-ref>}: source state reference
\item \texttt{tgt=<state-ref>}: target state reference
\item \texttt{events=\{event1, event2, ...\} }: list of events of
  which each may trigger the transition (\texttt{or}).
\item \texttt{guard}: side-effect free function that returns
  \texttt{true} or \texttt{false}. If false will inhibit transition.
\item \texttt{effect}: function that is executed when the transition
  is taken.
\item \texttt{pn=<number>}: Priority number. Transitions with larger
  numbers take priority in case of conflicting transitions.
\end{itemize}

\subsubsection{Description}

Transitions define how the FSM changes state when events are received.
\texttt{<state-ref>} can be \textit{absolute} ``root.s1.s2'',
\textit{local} ``s1'' or \textit{relative} (``.subst1.subst2'').
Transitions may cross state boundaries or be layered on top of deeper
nested states by parent states using the relative notation.

\subsection{Connectors}
\label{sec:connectors}

\begin{verbatim}
    rfsm.connector{}
    rfsm.conn{} -- short form
\end{verbatim}

\subsubsection{Description}

Connectors chain transitions into composite transitions or define
different entry and exit points of composite states. A connector is
\textit{never} active.

\section{Loading, Instantiating and Advancing}

\subsection{Loading and Instantiating}

\begin{itemize}
\item \texttt{model=rfsm.load(filename)}: load a rFSM model from a file.
\item \texttt{model=rfsm.load\_str(str[, name])}: load a model from a
  string.
\item \texttt{fsm=rfsm.init(model)}: instantiate and validate a rFSM
  model. Returns \texttt{false} on error.
\end{itemize}

\subsection{Advancing rFSM instances}

\begin{itemize}
\item \texttt{idle=rfsm.step(fsm[, N])}: \texttt{step} a rFSM
  instance. Executes at most \texttt{N} (default 1) transitions or doo
  cycles. Returns \texttt{true} if the fsm is idle.
\item \texttt{rfsm.run(fsm)}: step until there are no new events and
  no active \texttt{doo} function.
\item \texttt{rfsm.send\_events(fsm, event1, event2, \dots)}: send
  events to the internal fsm queue.
\item \texttt{rfsm.reset(fsm)}: reset to the inactive state; it is
  re-entered on the next step.
\end{itemize}

\subsubsection{Description}

The basic step consists of the following: \textbf{1.} retrieve new
events using \texttt{getevents} hook. \textbf{2.} Find enabled
transitions starting from \texttt{root} state to active
leaf. \textbf{3.} If enabled transition found $\rightarrow$
execute. \textbf{4.} elseif active \texttt{doo} $\rightarrow$ run
it. \textbf{5.} discard current events.

After each \texttt{step} exactly \textbf{one} leaf-state will be
active.

\subsection{Inspecting}

\begin{itemize}
\item \texttt{rfsm.get\_actleaf\_fqn(fsm)}: fqn of the active leaf
  state (or \texttt{nil})
\item \texttt{rfsm.get\_active\_conf(fsm)}: list of active state fqns
  from root down to the leaf
\end{itemize}

\section{Extensions}
\label{sec:extensions}

Extensions are enabled by \texttt{require}-ing them alongside the model.

\subsection{Tracing: \texttt{rfsm.pp}}
\label{sec:debugging}

Enable state entry and exit debug messages:

\begin{verbatim}
local pp = require("rfsm.pp")
fsm.dbg = pp.gen_dbgcolor("fsmX",
                          { STATE_ENTER=true,
                            STATE_EXIT=true }, false)
\end{verbatim}
\medskip
Most important debug IDs are:
\begin{verbatim}
STATE_ENTER, STATE_EXIT, EFFECT, DOO, EXEC_PATH,
ERROR, HIBERNATING, RAISED, TIMEEVENT
\end{verbatim}

\subsection{Time Events: \texttt{rfsm.timeevent}}

\begin{verbatim}
local timeevent = require("rfsm.timeevent")
timeevent.set_gettime_hook(gettime)
return rfsm.state {
   trans{ src="sA", tgt="sB",
          events={ timeevent.e_after(3) } },
   ...
}
\end{verbatim}

\subsubsection{Description}
\texttt{e\_after(t[, id])} fires \texttt{t} seconds after the source
state was entered, \texttt{e\_at(t[, id])} at the absolute time
\texttt{t}. Instead of a number, \texttt{t} can be a function that
returns the timeout and gets \texttt{id} passed. The old
\texttt{"e\_after(3)"} string syntax still works.

The \texttt{gettime} function returns the current time as a single
value in nanoseconds, e.g.\ for second resolution events:
\begin{verbatim}
function gettime() return os.time() * 1e9 end
\end{verbatim}

\textit{Note:} These timeevents only work for periodically triggered
components, they can not wake up an idle fsm.

\subsection{More Extensions}

\begin{itemize}
\item \texttt{rfsm.emem}: per state event memory: table
  \texttt{emem} counts the events received while the state is active.
\item \texttt{rfsm.await}: event \texttt{"await(e1, e2)"} triggers
  the transition once both events were received, possibly in
  different steps.
\item \texttt{rfsm.checkevents}: warn about unknown events at runtime.
  Load it after other event transforming extensions.
\end{itemize}

\subsection{Sequential AND state: \texttt{rfsm.ext}}

\begin{verbatim}
    local ext = require("rfsm.ext")
    seqAND = ext.seqand {
       subfsm1=rfsm.init(rfsm.load("subfsm1.lua")),
       subfsm2=...
    }
\end{verbatim}

\subsubsection{Fields}

\begin{itemize}
\item \texttt{order}: table of substate names that indicate the
  desired execution order. Not mentioned states are executed last.
\item \texttt{seqanddbg}: if true print debug info
\item \texttt{step}: number of steps to advance each time.
\item \texttt{run}: if true, don't step but \texttt{run}.
\item \texttt{idle\_doo}: doo flag to be returned by seqand yield.
\end{itemize}

\subsubsection{Description}
Specialized state that \texttt{step}'s or \texttt{run}'s the
initialized substates in a serialized manner inside the \texttt{doo}
function of the seqand state.

\section{Tools}

\begin{itemize}
\item \texttt{tools/rfsm-sim model.lua}: interactive simulator,
  \texttt{help()} lists the commands.
\item \texttt{tools/rfsm2plantuml model.lua}: write a PlantUML state
  diagram \texttt{model.puml}.
\item \texttt{tools/rfsm2json model.lua}: convert a model to JSON
  (needs \texttt{lua-json}).
\end{itemize}

\section{Complete Example}
\begin{verbatim}
local rfsm = require("rfsm")
local pp = require("rfsm.pp")
local timeevent = require("rfsm.timeevent")
local state, trans = rfsm.state, rfsm.trans
return state {
   dbg=pp.gen_dbgcolor("robot"),
   entry=function() enable_robot() end,
   exit=function() disable_robot() end,
   stopped = state{},
   moving = state {
      entry=function() start_motor() end,
      exit=function() stop_motor() end,
      doo=function()
         while true do
            compute_next_pos()
            rfsm.yield(true)
         end
      end,
   },
   trans{ src="initial", tgt="stopped" },
   trans{ src="stopped", tgt="moving", events={"e_start"} },
   trans{ src="moving", tgt="stopped",
          events={"e_stop", timeevent.e_after(5)} },
}
\end{verbatim}
